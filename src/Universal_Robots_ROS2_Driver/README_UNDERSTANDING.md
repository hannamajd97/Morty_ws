# Understanding `Universal_Robots_ROS2_Driver` (Humble)

This is a “map” of what is inside this repo and how the pieces connect, so you can debug and customize your setup with confidence.

## What each package is for

- `ur_robot_driver` (the actual driver)
  - Talks to the robot / URSim via the UR client library (RTDE, script sender, dashboard, etc.).
  - Starts `ros2_control` and loads controllers.
  - Publishes robot state (joint states, TF via `robot_state_publisher`), and exposes services/actions used by higher-level stacks.
  - Main entrypoint launch: `ur_robot_driver/launch/ur_control.launch.py`

- `ur_calibration` (calibration extraction tool)
  - Reads the robot’s factory calibration and writes a YAML.
  - That YAML is passed to the driver as `kinematics_params_file:=...`
  - Without it, your TCP pose in ROS can be wrong even if joints look fine.

- `ur_controllers` (UR-specific controller implementations)
  - Extra controllers and helper nodes for UR robots (beyond “generic” ros2_control controllers).

- `ur_dashboard_msgs`
  - Message/service definitions for the dashboard client (power on, brake release, play/stop program, etc.).

- `ur_moveit_config` (example MoveIt2 config)
  - Not required for driving the robot.
  - Provides a ready-to-run MoveIt pipeline (SRDF, planners, controller interface config, RViz config).
  - Entry launch: `ur_moveit_config/launch/ur_moveit.launch.py`

- `ur` (metapackage)
  - Convenience “install everything” package.

- `ur_bringup` (deprecated wrappers)
  - Old convenience launch files that forward to `ur_robot_driver`.
  - In Humble it still exists, but the repo warns it will be removed in newer distros.

## The “big picture” launch flow

### 1) Driver bringup (`ur_robot_driver`)

`ros2 launch ur_robot_driver ur_control.launch.py ...` does roughly:

1. Builds `robot_description` by running `xacro` on a URDF/Xacro file
   - Controlled by `description_package` + `description_file`
   - And parameterized by `ur_type`, `robot_ip`, `kinematics_params_file`, safety params, tool comm params, etc.
2. Starts a `ros2_control` node
   - Real hardware: `ur_ros2_control_node` (connects to robot/URSim)
   - Fake hardware: `ros2_control_node` (mirrors commands to states for testing)
3. Spawns controllers from `controllers_file`
4. Optionally starts RViz (driver-side RViz is for state/TF visualization, not MoveIt)

### 2) MoveIt bringup (`ur_moveit_config`)

`ros2 launch ur_moveit_config ur_moveit.launch.py ...` does roughly:

1. Builds a `robot_description` (same idea: `xacro` → XML string parameter)
2. Builds `robot_description_semantic` from SRDF/Xacro
3. Starts:
   - `move_group` (planning + execution action servers)
   - RViz with the MotionPlanning panel
   - optional `moveit_servo`

MoveIt does **not** replace the driver. It connects to the controllers that the driver exposes.

## The few parameters that matter most

These show up again and again in launch files:

- `ur_type`
  - Chooses robot family/size and selects the matching description/config folder (e.g. `config/ur3e/...`).

- `robot_ip`
  - How the driver reaches the robot/URSim.
  - For MoveIt-only visualization it’s often a placeholder, but for the driver it must be correct.

- `kinematics_params_file`
  - The calibration YAML (recommended for real hardware).
  - Generated by `ur_calibration`.

- `use_fake_hardware` / `fake_sensor_commands`
  - Lets you bring up ros2_control without a robot connected.
  - Great for developing MoveIt / planning code before you have hardware access.

- `description_package` + `description_file`
  - Controls what URDF/Xacro is used to build `robot_description`.
  - If you attach custom tooling (like a gripper), this is usually what you override.

## “Where do I change X?”

- Robot IP / connection / ports / dashboard / IO: `ur_robot_driver`
- Robot geometry (links/joints/meshes): your URDF/Xacro in `ur_description` (or your custom description package)
- Calibration: `ur_calibration` output YAML passed into driver
- Planning groups / end effector / allowed collisions: SRDF (MoveIt config)
- Planner settings: `ompl_planning.yaml` (MoveIt config)
- MoveIt controller mapping: `controllers.yaml` (MoveIt config)
